# 中文论文与报告的表达模式

本参考用于初稿撰写、局部润色与交付前语言验收。先组织段落的主张、依据与推进，再处理词句。词语、句式、标点、句长或段落形态都是复核线索，只有造成事实不清、逻辑不明、证据越界、指代困难、机械重复或不符合目标学术语体时才修改。

三项并列、问句、比喻、被动表达、名词化、长句、短句、分号、显式连接词以及某种句段分布都不是独立错误。表达审校遵循 [研究严谨性与证据](rigor-and-evidence.md) 的主张边界与 [文档建模与审计流程](document-model-and-audit.md) 的信息锚点和功能保护。

## 一、段落主张与信息推进

必要背景明确后，段落直接说明研究对象、问题、方法、判断或结果，围绕一个主要任务组织依据、解释和条件；条件与主张可以同句出现。不要先回应想象中的质疑，再绕回正文。摘要、引言的贡献段、段首和结论尤其检查主张是否被铺垫、辩解和重复限定遮住；局限性段落仍应直接说明局限及其影响。

遇到“随着……不断发展”“众所周知”“在深入讨论之前”“值得注意的是”等起笔，检查它是否提供必要的时间、政策、范围、研究动机或歧义说明；有功能时具体化，无增量时删除。段末落在结果、解释边界或下一步输入上；“由此可见”“综上所述”等引导语之后应有信息推进，同义复述应合并。

“不是 X，而是 Y”等对照只在 X、Y 的区分本身参与定义、比较或推理时保留。只为引出 Y 而临时设立的 X 可删，直接陈述 Y；真实概念辨析和竞争解释不按句式删除。

## 二、限定与防御性说明

先识别整句的研究功能，再决定处置，不按“不表示、仅、尚未、仍需”等词语裁决：

| 功能 | 判断与处置 |
|---|---|
| 必要边界或辨析 | 删除会改变主张的适用范围、确认状态、因果含义或概念区分时保留功能；定义与位置按 [证据边界](rigor-and-evidence.md#必要边界的安置与复用) 处理。 |
| 工作记录或补证任务 | 能说明方法、配置要求、核验依据或验收口径的，转为相应研究表述；纯作者待办移出正文。 |
| 无功能辩护或重复澄清 | 为假设性质疑而增加、或已有定义和图例已解决的内容，删除或合并；不另造更正向的空句。 |

对候选句依次判断：它改变读者对哪项事实或推理的理解；删除会损失什么；是否已由主张本身或前文说明；若仍有必要，应放在哪里。只把有增量的部分留在适当位置，后文用稳定术语承接。

主张过宽时，先修正对象、范围、比较基准或动词强度，使句子本身与证据相称。“可能、或许、潜在、在某种程度上”等层叠时，区分真实不确定性与重复缓和；材料有依据时写清不确定性来自何种设计、测量或样本条件。仅有猜测时仍保留猜测强度，不自行补造不确定性的原因，也不把“提示”升级为“证明”。

真实排除标准、阴性结果、未验证状态、因果与分类边界、局部证据冲突和风险提示按研究需要保留。去防御性处理的目标是减少无功能说明，不是删除负面信息。脚本命中只定位候选，不能自动改写。

## 三、从工作记录到论文表述

检查读者能否脱离作者的工作环境和协作上下文理解正文。材料来源使用读者可识别、可追溯的名称；核验内容说明它如何影响变量定义、样本处理或结果解释。根据整句功能决定保留、改写、移位或删除，不只把“本地说明文件”换成“随附说明”。

正文直接交代已形成的定义、方法、结果、模型或要求。构成研究依据或复现条件的文件名称、版本差异、核验方法、失败尝试和执行顺序按需保留；无研究功能的查文件、比版本、排查问题过程以及聊天、编辑、待办和制作说明移出正文。出版规范要求的图注、表注、脚注、数据可用性声明和来源项按目标格式保留。原句已准确清楚时保持原样。

以下为匿名化的通用示例，仅示范在给定信息范围内的处理，不对应可引用的研究材料，也不能作为固定句库：

| 原句或已知语境 | 按功能处理 |
|---|---|
| 本文无意给出覆盖所有城市的理论，只分析 2021—2023 年 A、B 两市公交换乘记录。 | 本文分析 2021—2023 年 A、B 两市的公交换乘记录。 |
| 当前形成的是逻辑血缘，不表示已形成生产物理血缘；核验后者需取得 DDL、SQL 或 ETL 任务。 | 当前成果为逻辑血缘；生产物理血缘尚未确认，其核验需取得 DDL、SQL 或 ETL 任务。 |
| 六个分支表示可能的形成条件和验证入口，不构成已经确认的原因排序。 | 六个分支列示可能的形成条件及验证入口，分支排列不表示已确认的原因排序。 |
| 已知图例完整说明“虚线表示反馈路径”；正文再次解释相同编码。 | 删除重复编码说明；反馈机制本身有分析价值时解释机制。 |
| 假设某调查的编码规则将 99 定义为缺失值；草稿写“查看本地说明文件后排查出 99 的含义，清洗时将其置为空值”。 | 依据该调查的编码规则，将取值 99 按缺失值处理。 |

## 四、具体动作与准确命名

“构建机制、形成体系、实现赋能、提供支撑、推动落地、发挥作用”等抽象组合如果隐藏研究动作，应恢复执行者、材料、操作和可核验结果。成果名称的完整性与层级按通用证据规则审计，语言终校只负责让名称和实际内容一致，不用更宏大的词替换具体成果。

没有正式定义的项目化组合词应改为通行术语，或在首次承担分析功能前给出足够定义。术语重复有助于追踪，不以近义词轮换同一对象来制造变化。

### 术语可理解性与受众适配

专业性或低频本身不构成修改理由。审校术语时同时判断：它是否承担必要的学科概念区分，是否来自正式标准或目标领域惯例，目标读者是否熟悉，后文是否反复使用，以及通俗表达能否保持原有含义和边界。用户、学校、导师或项目已经确认的术语口径优先。

根据判断采用三种处置：

- **保留**：术语精确、目标读者熟悉或需要与文献和标准保持一致；必要时在首次出现处定义。
- **解释后简称**：术语有独立概念价值但对目标读者不够直观，首次用通俗表达说明，再保留稳定简称。
- **按语境改写**：术语只是行业黑话、项目缩略语或抽象包装，通俗表达能够完整承载原意时，直接写出对象、动作、关系或状态。

不得用通俗化削弱方法含义、证据强度或状态边界。例如，“代理指标”若表示无法直接测量目标概念时采用的替代性指标，应先解释后保留该方法含义，不能一律弱化成“临时衡量依据”；“闭环”在治理语境中已被目标读者接受时，可以首次说明为从触发、处置到再次验证的完整过程，后文保持稳定名称。相反，用户明确要求成稿禁用某个生僻词时，在等义前提下采用其确认的通俗表达。

用户提供术语偏好时，可在工作底稿中记录 `原术语 → 当前语义 → 目标读者 → 保留/解释/改写 → 成稿表达`。该表是当前文稿的受众适配约束，不自动升级为其他学科或文稿的全局禁词表。

## 五、指代与中英文处理

“该资料、上述对象、相关内容、这一结果、部分系统、其”等指代必须有唯一先行词。先行词较远或可能指向多个对象时直接恢复名称。

同一外文术语采用一个确认的中文名称和缩写。首次出现按目标规范给出中英文或缩写，后文不反复双写；不同译名只有在比较学术传统或概念边界时并列。

## 六、翻译腔与句法层级

检查过长前置定语、主谓距离过远和多层“对……的……的……进行……”。中文通常先明确对象和动作，再补充条件；拆句时保留原有限定关系。

“对于 X 来说”“就 X 而言”“在 X 方面”只在切换比较维度、限定范围或消除歧义时保留。X 能直接充当主语或对象且话题壳无功能时，直接进入判断。

连续“的”链应区分分类、所属和动作关系，可通过恢复动词、使用“其中”或“由……构成”、拆分定义与限定来处理；不按字数机械删词。“其”只在指向唯一且能缩短句子时使用，相邻句反复出现时恢复明确主语。

名词化只有在隐藏执行者、动作、对象或使修饰层级难以解析时才改写；结构清楚且符合学术语体时保留。

## 七、句法、节奏与衔接

一个句子应有可识别的主要判断和必要限定。长句本身不是错误；背景、方法、结果和意义被逗号或分号串联并导致判断层级难以理解时，才按语义边界拆分。

句长变化来自真实的条件、比较、机制、结果和限定关系。统计发现句段均一时，继续检查句法骨架、段落功能和信息推进是否同时同构；没有结构问题则不为制造波动而拆句、补写空句或替换稀有词。

连接词必须标记真实关系：“同时”表示并行，“因此”表示推论，“其中”引出集合成员，“相比之下”需要明确比较对象。重复连接词只是复核入口；应修复实际的机械列举或关系缺失，而不是轮换同义词。

并列数量服从真实分类和权重。确有三个对象时保留，不因“三项式”外观随意增删；不同权重的内容不强写成对称排比。

## 八、归因与评价语气

“研究表明、专家认为、业内普遍认为、相关资料显示”应紧邻可核验来源。来源只与主题相关而不支持相邻命题时，调整命题或来源。

评价他人研究时，针对其论点、方法、数据和证据指出具体贡献或不足，不推测作者动机，不以贬低他人突出本文。转述应准确保留原意，并清楚区分他人的发现与本文的结果。

“至关重要、深刻揭示、显著赋能、开创性、全方位、奠定坚实基础、前景广阔”等评价需要具体比较、机制或结果支持。缺少支持时改为可观察事实。强结论词的证据要求由通用证据规则决定，不能只靠降调词替换掩盖证据缺口。

## 九、终校步骤

1. 核对数字、公式、引文、术语、确认状态和限定，确认表达调整前后等义。
2. 检查段落的主要任务及段首、段末和相邻段的信息推进；论证问题先于表面润色处理。
3. 按本参考第二、三节处理限定、重复辩护和工作记录，检查安置位置及读者所需语境。
4. 检查指代、术语与受众适配、句法、归因、评价语气和衔接，清除协作残留与异常格式。
5. 没有新的具体问题时结束；必要否定和真实不确定性不是未完成修改的标志。
